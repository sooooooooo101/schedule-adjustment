# 日程調整アプリ 設計書（ドラフト）

最終更新: 2026-10-16
状態: 目標とするプロダクト仕様。現行コードの機能・実装状況は [docs/implementation-status.md](implementation-status.md) を参照。設計書の記載だけで実装済みと判断しない。

## 1. 目的

この文書は目標仕様であり、現在利用できる機能の一覧ではない。機能の実装状態はコードと実装状況文書で照合する。

作成者の日程調整の手間をなくすためのツール。Google アカウントでログインできる人は誰でも作成者になれる。販売・App Store 配布はしない。調整への回答は、共有リンクを受け取った人がログインせずに行う。

解決したいこと:

- スマホから調整ページを作るのが面倒 → 自然文で頼むだけで候補日を作る
- 回答の入力が長い → 友人もログインなしで、自然文かタップで答えられる
- 確定後の登録が面倒 → ワンタップで Google カレンダー登録・招待・Meet URL 発行

## 2. スコープ

### やること（MVP）

1. 作成者が自然文で依頼し、AI が自分の Google カレンダーの空きと照合して候補日時を出す
2. 候補を確認・修正して調整ページを作り、共有リンクを LINE などで送る
3. 回答者はリンクを開き、名前を入れて回答する（ログイン不要）
   - 自然文で回答（例:「火曜の夜と木曜ならいける」）→ AI が ○△× に変換 → 本人が確認して送信
   - または候補ごとに ○△× をタップ
4. 作成者は回答一覧を見て候補を確定する
5. 確定すると次をまとめて実行する
   - 作成者の Google カレンダーに予定を作成
   - Google Meet の URL を自動発行（任意でオフ）
   - メールアドレスを入れた回答者に Google カレンダーの招待を送信
   - 回答者向けの確定ページに日時・Meet URL・「カレンダーに追加」（Google カレンダー用リンクと .ics）を表示

### やらないこと

- 他人が作った TONTON への自動回答（画面の自動操作は壊れやすく、利用規約上の懸念もあるため）
- Zoom 連携（Meet のみ。必要なら後で URL 手入力欄を足す）
- 販売、App Store 配布
- 繰り返し予定、リマインド通知

## 3. 画面と流れ

スマホ縦画面を前提に設計する。ホーム画面に追加して使えるよう PWA にする。

### 作成者側

1. ホーム: チャット風の入力欄が1つと、進行中の調整一覧
2. 入力例:「来週火曜の午後か水曜で、AさんBさんと1時間。Meet付きで」
3. 候補確認: AI が出した候補をカードで表示。削除・時刻修正・追加ができる。タイトルと所要時間、Meet の有無もここで確認
4. 作成: 共有リンクを発行し、共有シート（Web Share API）で LINE などに送る
5. 回答一覧: 候補 × 回答者の ○△× 表。○の多い候補を強調表示
6. 確定: 候補を選んで「この日で確定」→ 予定作成・招待・Meet 発行

### 回答者側

1. リンクを開く → 名前（必須）とメールアドレス（任意、招待を受け取りたい人だけ）を入力
2. 自然文で答えるか、候補ごとにタップで答える
3. 自然文の場合は AI の変換結果を ○△× で表示し、本人が修正してから送信
4. 確定後に同じリンクを開くと確定ページになる

## 4. 構成（案）

| 層 | 採用案 | 理由 |
|---|---|---|
| フロント / API | Next.js（App Router）on Vercel | スマホ向け Web とサーバー処理を1つにまとめられる。無料枠で足りる見込み |
| データベース | Neon（Postgres、Vercel Marketplace 経由） | 無料枠で足りる。使わないときは自動休止し、アクセスで自動起動する（Supabase 無料プランの「7日で一時停止」を避けるため変更） |
| 認証 | 誰でも Google ログインで作成者になれる（複数ユーザー）。各ユーザーが Gmail と Workspace など複数アカウントを連携できる | 回答者はログインなし |
| AI | Gemini API（Flash-Lite 系、無料枠） | 自然文 → 候補日時、自然文回答 → ○△× の2用途。JSON の形を固定して出力させる。接続部分は差し替え可能にする |
| カレンダー | Google Calendar API（freeBusy で空き取得、events.insert で作成） | Meet は conferenceData で発行、招待は sendUpdates=all |

タイムゾーンは Asia/Tokyo 固定とする。

### 複数 Google アカウント

作成者は個人の Gmail と Google Workspace の両方を使うため、複数アカウントを連携できるようにする。

- 空き確認: 連携中のすべてのアカウントの freeBusy を合算する
- 予定作成: 「メイン」のアカウント（最初に連携したもの）のカレンダーに作る。確定時に変更できるようにする
- リフレッシュトークンは AES-256-GCM で暗号化して保存する

### OAuth スコープ

`calendar.events`（予定作成・Meet 発行・招待）と `calendar.freebusy`（空き確認）のみ。カレンダーの中身を読む権限は求めない。

### UI の方針

Apple の Human Interface の考え方（apple-design スキル）に沿う。

- 押した瞬間に反応する（離したときではなく）。ダブルタップ拡大の待ちを消す
- iOS 風のグループ化リスト、大見出し、主操作は親指の届く下端に置く
- 色はライト／ダークで役割ごとに切り替えるトークンで管理する
- フォントは M PLUS 2（next/font で自前配信）。端末を問わず同じ見た目にする。読み込み前は端末標準の日本語フォントで表示する
- モーションを減らす・透明度を下げる・コントラストを上げる設定に追従する
- 候補カードのスワイプ削除やボトムシートを作る段階で、スプリングアニメーション（中断可能、指の速度を引き継ぐ）を導入する

## 5. データモデル（案）

- events: id, title, duration_min, status（open / confirmed）, confirmed_slot_id, meet_enabled, meet_url, gcal_event_id, created_at
- slots: id, event_id, start_at, end_at
- responses: id, event_id, name, email（任意）, comment, created_at
- answers: response_id, slot_id, value（yes / maybe / no）

共有リンクは推測できない長い ID を使う（例: `/e/{ランダム22文字}`）。

## 6. AI の使い方

### 段階方式（AI の性能と無料枠の上限をコードで補う）

1. ルールで解釈する：「明日」「来週火曜」「午後」「19時」などのよくある言い方は正規表現と日付計算で処理し、AI を呼ばない
2. ルールで読めなかった場合だけ Gemini に渡す。AI には「来週・火曜・午後・60分」のような中間形式だけを出させ、実際の日時への変換・空き時間との照合はコードで行う
3. AI の出力は zod で検証し、形が崩れていればエラー内容を添えて1回だけやり直す
4. 無料枠の上限に達したら、手入力の画面に切り替える。必要になれば有料の安いモデルを予備に足す
5. 例文と正解の組（数十件）を用意し、モデルの正解率を自動で測る

### AI に渡すデータ

入力文と今日の日付だけ。カレンダーの予定や空き時間は渡さない（Gemini の無料枠では入力が Google の製品改善に使われるため）。無料枠はアプリの API キー単位なので、全ユーザーで共有になる点に注意。ユーザーごとに1日の回数上限を設ける。

### 作成時の解釈

入力: 自然文、今日の日付、作成者の空き時間（freeBusy の結果）
出力: タイトル、所要時間、Meet 有無、候補日時の配列

「来週」「午後」などの曖昧な表現は、解釈結果を候補カードに明示して作成者が確認できるようにする。AI の出力をそのまま確定させない。

### 回答時の解釈

入力: 自然文の回答、候補日時の一覧
出力: 候補ごとの yes / maybe / no

回答者が送信前に必ず確認・修正できる画面を挟む。

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 回答ページは誰でも開けるため、AI の API を大量に呼ばれて費用がかかる | 調整ごと・IP ごとの回数制限、入力文字数の上限 |
| Google OAuth アプリを「テスト」状態のまま使うと、リフレッシュトークンが7日で失効する（Google の公式ヘルプで確認済み） | 公開ステータスを「本番環境」（未審査）にして運用する。ログイン時に未確認アプリの警告が出るが、自分用なので許容する |
| Google カレンダーを使わない友人がいる | 確定ページで .ics を提供。招待メールは Google 以外のメールアドレスにも届くはず（要確認） |
| AI の日時解釈ミス | 作成時・回答時とも、確定前に人が確認する画面を必ず挟む |
